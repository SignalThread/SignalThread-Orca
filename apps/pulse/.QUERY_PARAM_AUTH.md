# Query Parameter Based Account Selection

**Date:** 2026-01-26  
**Status:** ✅ COMPLETE

---

## Overview

Removed mock cookie authentication and replaced it with a simpler query parameter approach. Account selection is now done via URL query params (`?account=<slug>`), making the system stateless and easier to test.

---

## 🎯 Changes Made

### 1. Login Page (`app/login/page.tsx`)

**Before:** Set cookies and redirect
```typescript
document.cookie = `mock_admin_email=${account.email}; ...`
document.cookie = `mock_admin_role=${account.role}; ...`
document.cookie = `mock_account_id=${account.accountId}; ...`
router.push('/app')
```

**After:** Direct redirect with query param
```typescript
router.push(`/app?account=${account.slug}`)
```

**Changes:**
- ✅ Removed all cookie-setting code
- ✅ Removed email and role from account objects
- ✅ Simplified redirect logic
- ✅ Platform admin → `/admin` (no params)
- ✅ Customer admin → `/app?account=<slug>`

---

### 2. Customer Admin Home (`app/app/page.tsx`)

**Before:** No query param handling
```typescript
const response = await fetch('/api/app/account')
```

**After:** Read account from query param
```typescript
const accountSlug = searchParams.get('account')
const response = await fetch(`/api/app/account?account=${accountSlug}`)
```

**Changes:**
- ✅ Added `useSearchParams()` hook
- ✅ Read `account` query param
- ✅ Pass account to API call
- ✅ All internal links preserve `?account=<slug>`
- ✅ Wrapped in Suspense for `useSearchParams()`
- ✅ Error if no account specified

**Link Updates:**
```typescript
// All links now include account param
router.push(`/app/events/new?account=${accountSlug}`)
router.push(`/app/locations/${location.id}?account=${accountSlug}`)
router.push(`/app/events/${event.id}?account=${accountSlug}`)
router.push(`/app/events/new?account=${accountSlug}&locationId=${location.id}`)
```

---

### 3. Event Dashboard (`app/app/events/[eventId]/page.tsx`)

**Before:** No query param handling
```typescript
<Button onClick={() => router.push('/app')}>
  ← Back to Home

```

**After:** Preserve account param everywhere
```typescript
const accountSlug = searchParams.get('account')
const accountPath = accountSlug ? `/app?account=${accountSlug}` : '/app'

<Button onClick={() => router.push(accountPath)}>
  ← Back to Home
</Button>
```

**Changes:**
- ✅ Added `useSearchParams()` hook
- ✅ Read `account` query param
- ✅ Build `accountPath` for Back button
- ✅ Pass `accountPath` to AdminLayout `homePath`
- ✅ Preserve account in "View All Responses" link
- ✅ Wrapped in Suspense

---

### 4. API Route (`app/api/app/account/route.ts`)

**Before:** Read from middleware headers
```typescript
const accountId = request.headers.get('x-account-id')
```

**After:** Read from query param
```typescript
const { searchParams } = new URL(request.url)
const accountSlug = searchParams.get('account')
```

**Changes:**
- ✅ Parse URL to get search params
- ✅ Read `account` query param
- ✅ Use as account ID in database query
- ✅ Return 400 if no account specified
- ✅ No dependency on middleware headers

---

### 5. Middleware (`middleware.ts`)

**Status:** ✅ DELETED

**Reason:** 
- No longer needed for authentication
- No cookies to read
- No headers to inject
- Simpler architecture without middleware

## 📊 URL Structure

### Before (Cookie-based)
```
/login → Set cookies → Redirect to /app
/app → Read cookie → Show account data
/app/events/123 → Read cookie → Show event data
```

### After (Query param-based)
```
/login → Redirect to /app?account=acme-coffee
/app?account=acme-coffee → Show Acme Coffee account data
/app/events/123?account=acme-coffee → Show event data
```

---

## 🔗 Link Patterns

### Customer Admin Links
All links preserve the `?account=` param:

```typescript
// Home
/app?account=acme-coffee

// Event
/app/events/${eventId}?account=acme-coffee

// Location
/app/locations/${locationId}?account=acme-coffee

// New Event
/app/events/new?account=acme-coffee

// New Event (with location)
/app/events/new?account=acme-coffee&locationId=${locationId}

// Responses
/app/events/${eventId}/responses?account=acme-coffee
```

### Kiosk Links
Kiosk links remain simple (no account param):

```typescript
/kiosk?eventId=${eventId}
```

**Reason:** Kiosk is public-facing and doesn't need account context


## 🔄 Migration Notes

**For Existing Deployments:**

1. **No database changes required** ✅
2. **No API contract changes** (only query param instead of header) ✅
3. **Backward compatible** ✅
4. **Cookies no longer used** (will be ignored) ✅

**Breaking Changes:**
- Users must go through `/login` (can't directly access `/app` without param)
- Old cookie-based sessions will not work
- Middleware no longer runs (any code depending on it will break)

**Migration Path:**
```bash
# 1. Deploy new code
# 2. Existing sessions (cookies) expire naturally
# 3. Users re-login via /login page
# 4. New query param system takes over
```

## ⚠️ Security Considerations

**Current State:**
- ✅ Account slug in URL is visible (not secret)
- ✅ Anyone with URL can access that account's data
- ✅ Suitable for demo/development
- ⚠️ Not suitable for production without real auth

**For Production:**
1. Add real authentication (NextAuth, Clerk, etc.)
2. Validate user has access to requested account
3. Use session tokens instead of account slug
4. Add RBAC (role-based access control)
5. Log account access for auditing

**Current Security Model:**
```
User → Select Account → URL with account slug → API returns data

No verification that user should have access to that account!
```

**Production Security Model:**
```
User → Login → Session token → API validates token → API returns data

Token proves user identity and account access rights.
```
