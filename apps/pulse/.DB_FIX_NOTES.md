# Database Connectivity Fix - Session Pooler for Runtime

**Date:** 2026-01-25  
**Issue:** Runtime gets "circuit breaker open" errors via Supabase transaction pooler (port 6543)  
**Solution:** Switch to session pooler (port 5432) without `pgbouncer=true` for runtime

---

## What Changed

### `.env.local` Configuration

**OLD (Transaction Pooler):**
```env
DATABASE_URL=...pooler.supabase.com:6543/postgres?sslmode=require&pgbouncer=true&connection_limit=1
DIRECT_URL=...pooler.supabase.com:5432/postgres?sslmode=require
```

**NEW (Session Pooler for Both):**
```env
DATABASE_URL=...pooler.supabase.com:5432/postgres?sslmode=require
DIRECT_URL=...pooler.supabase.com:5432/postgres?sslmode=require
```

### Key Points

- ✅ **Port 5432** (session pooler) instead of 6543 (transaction pooler)
- ✅ **NO `pgbouncer=true`** parameter (this was causing circuit breaker issues)
- ✅ **Same pooler** for both runtime (DATABASE_URL) and migrations (DIRECT_URL)
- ✅ Prisma CLI works: `npx prisma db execute --stdin <<< "SELECT 1;"` ✅ passes

## Why This Works

### Transaction Pooler (Port 6543) Issues

- Uses PgBouncer in transaction mode
- Requires `pgbouncer=true` parameter
- Has strict connection limits
- Can hit "circuit breaker open" when pooler itself can't reach upstream DB
- **Problem:** If Supabase DB is IPv6-only and local dev is IPv4-only, pooler circuit breaker opens

### Session Pooler (Port 5432) Benefits

- Uses PgBouncer in session mode
- Does NOT require `pgbouncer=true` parameter (actually breaks if you include it)
- More stable for local dev
- Better for Prisma's connection pattern
- Still uses connection pooling, just different mode

2. **Check Password Encoding:**
   ```bash
   # If password has special chars, they must be URL-encoded
   # Example: ! → %21, # → %23, @ → %40
   ```

3. **Check Supabase Dashboard:**
   - Project Settings → Database → Connection Pooling
   - Verify port 5432 is session pooler
   - Check if database is paused (free tier auto-pauses)

4. **Check Prisma Client Generation:**
   ```bash
   npx prisma generate
   ```
