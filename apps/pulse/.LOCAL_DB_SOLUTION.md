# Local PostgreSQL Solution - IPv6 Connectivity Fix

**Date:** 2026-01-26  
**Issue:** Supabase IPv6-only database causing "Circuit breaker open" errors  
**Solution:** Local PostgreSQL via Docker for development

---

## 🔍 Root Cause

Your Supabase database is **IPv6-only** and your local network **lacks proper IPv6 connectivity**.

**Evidence:**
1. ✅ Network test succeeds: `nc -vz aws-1-us-east-2.pooler.supabase.com 5432` 
2. ✅ Prisma CLI works: `npx prisma db execute --stdin <<< "SELECT 1;"`
3. ❌ Runtime fails: "FATAL: Circuit breaker open"
4. ❌ Same error on both transaction pooler (6543) AND session pooler (5432)

**What's happening:**
- You can reach the Supabase **pooler** (PgBouncer)
- But the pooler **cannot reach the upstream IPv6-only database**
- After repeated failures, PgBouncer's circuit breaker opens to protect the system
- Your application gets the circuit breaker error

**Why CLI works but runtime doesn't:**
- Prisma CLI may have different timeout/retry logic
- Or it's hitting a cached connection
- But runtime consistently fails with fresh connections

---

## ✅ Solution: Local PostgreSQL

Use Docker to run PostgreSQL locally, completely bypassing IPv6 issues.

### Benefits

- ✅ **No IPv6 dependency** - runs on localhost (127.0.0.1)
- ✅ **Faster** - no network latency
- ✅ **Offline development** - works without internet
- ✅ **Consistent** - same for all team members
- ✅ **Free** - no Supabase limits
- ✅ **Easy reset** - `docker-compose down -v` for clean slate

## 🔧 Troubleshooting

### Issue: docker-compose: command not found

**Cause:** Docker Compose v2 uses `docker compose` (no hyphen)

**Solution:**
```bash
# Check Docker status
./CHECK_DOCKER.sh

# The setup script will auto-detect the correct command
./SETUP_LOCAL_DB.sh
```

### Issue: Cannot connect to Docker daemon

**Cause:** Docker Desktop is not running

**Solution:**
```bash
# Start Docker Desktop
open -a Docker

# Wait for Docker to start (look for whale icon in menu bar)
# Then try again
./CHECK_DOCKER.sh
```

### Issue: Port 5432 already in use

**Cause:** Another PostgreSQL instance is running

**Solution:**
```bash
# Find what's using port 5432
lsof -i :5432

# Option 1: Stop the other PostgreSQL
brew services stop postgresql

# Option 2: Use different port in docker-compose.yml
# Change: "5433:5432" and update .env.local to localhost:5433
```

### Issue: Docker not installed

**Solution:**
```bash
# Install Docker Desktop for Mac
# https://www.docker.com/products/docker-desktop

# Or via Homebrew
brew install --cask docker
```

### Issue: Migration fails

**Solution:**
```bash
# Reset and try again
docker-compose down -v
./SETUP_LOCAL_DB.sh
```

### Issue: Container won't start

**Solution:**
```bash
# Check logs
docker logs booth-audio-db

# Remove and recreate
docker-compose down
docker-compose up -d postgres
```

## 🔄 Switching Between Local and Supabase

If you want to switch back to Supabase (e.g., for production testing):

### Switch to Local (Development)

Edit `.env.local`:
```env
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/booth_audio?schema=public"
DIRECT_URL="postgresql://postgres:postgres@localhost:5432/booth_audio?schema=public"
```

Then restart:
```bash
./RESTART_DEV_SERVER.sh
```

### Switch to Supabase (Production Testing)

Edit `.env.local`:
```env
DATABASE_URL="postgresql://postgres.xcveazzoavnizefbcjfg:BoothAudioDev2026@aws-1-us-east-2.pooler.supabase.com:5432/postgres?sslmode=require"
DIRECT_URL="postgresql://postgres.xcveazzoavnizefbcjfg:BoothAudioDev2026@aws-1-us-east-2.pooler.supabase.com:5432/postgres?sslmode=require"
```

Then restart:
```bash
./RESTART_DEV_SERVER.sh
```

**Note:** Supabase will still have circuit breaker issues due to IPv6. Only use for testing when you have proper IPv6 connectivity.

For production, continue using Supabase. The IPv6 issue only affects local development.

Keep `.env.prod` with Supabase credentials:
```env
DATABASE_URL="postgresql://postgres.xcveazzoavnizefbcjfg:BoothAudioDev2026@aws-1-us-east-2.pooler.supabase.com:6543/postgres?sslmode=require&pgbouncer=true"
```
