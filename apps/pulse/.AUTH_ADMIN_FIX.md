# Auth Admin Access Fix

**Date:** 2026-01-26  
**Status:** ✅ FIXED

---

## 🐛 Bug Description

Magic-link login succeeded but SUPER_ADMIN users got error:
```
"No account specified. Please select an account from the login page."
```

---

## 🔍 Root Cause

The app incorrectly assumed **ALL** admin routes required account context (`?account=` query param). This assumption was wrong for SUPER_ADMIN users.

**Key Facts:**
- SUPER_ADMIN users do NOT have or need an account context
- `/admin` is platform-level and account-agnostic
- `/app` is account-scoped for customer admins
- Account selection should happen INSIDE `/admin`, not before it

---

## ✅ Fixes Applied

### 1. Auth Callback - Role-Based Redirect

**File:** `app/auth/callback/route.ts`

**Before:**
```typescript
// Always redirected to /app for everyone
const next = searchParams.get('next') ?? '/app'
return NextResponse.redirect(`${origin}${next}`)
```

**After:**
```typescript
// Redirect based on role
if (dbUser.role === 'SUPER_ADMIN') {
  // SUPER_ADMIN → /admin (no account context)
  return NextResponse.redirect(`${origin}/admin`)
} else {
  // ADMIN/MANAGER/VIEWER → /app with account context
  if (dbUser.accountId) {
    const account = await prisma.account.findUnique({
      where: { id: dbUser.accountId },
      select: { slug: true },
    })
    if (account) {
      return NextResponse.redirect(`${origin}/app?account=${account.slug}`)
    }
  }
  
  // No account assigned - error page
  return NextResponse.redirect(`${origin}/app?error=no_account_assigned`)
}
```

**Changes:**
- ✅ SUPER_ADMIN → `/admin` (platform-level, no account)
- ✅ Regular admins → `/app?account={slug}` (account-scoped)
- ✅ No account assigned → error page with clear message

### 2. Middleware - Account Context Auto-Injection

**File:** `middleware.ts`

**Added for `/app` routes:**
```typescript
// For /app routes, ensure account context exists
if (pathname.startsWith('/app') && !pathname.startsWith('/app/api')) {
  const accountSlug = request.nextUrl.searchParams.get('account')
  if (!accountSlug) {
    // Missing account context - get it from user's accountId
    const dbUser = await prisma.user.findUnique({
      where: { id: user.id },
      select: { accountId: true },
    })
    
    if (dbUser?.accountId) {
      const account = await prisma.account.findUnique({
        where: { id: dbUser.accountId },
        select: { slug: true },
      })
      if (account) {
        // Redirect with account context
        const url = request.nextUrl.clone()
        url.searchParams.set('account', account.slug)
        return NextResponse.redirect(url)
      }
    }
    
    // No account assigned - redirect to error page
    const url = request.nextUrl.clone()
    url.pathname = '/login'
    url.searchParams.set('error', 'no_account_assigned')
    return NextResponse.redirect(url)
  }
}
```

**Changes:**
- ✅ `/app` routes auto-inject `?account=` if missing
- ✅ Looks up user's `accountId` from database
- ✅ Redirects with proper account context
- ✅ Clear error if no account assigned

**Improved `/admin` access denial redirect:**
```typescript
if (dbUser?.role !== 'SUPER_ADMIN') {
  // Not a super admin - redirect to /app with their account context
  if (dbUser?.accountId) {
    const account = await prisma.account.findUnique({
      where: { id: dbUser.accountId },
      select: { slug: true },
    })
    if (account) {
      url.pathname = '/app'
      url.searchParams.set('account', account.slug)
      url.searchParams.set('error', 'admin_access_denied')
      return NextResponse.redirect(url)
    }
  }
  
  // No account - redirect to login
  url.pathname = '/login'
  url.searchParams.set('error', 'no_account_assigned')
  return NextResponse.redirect(url)
}
```

**Changes:**
- ✅ Non-SUPER_ADMIN trying to access `/admin` redirected to `/app` with their account slug
- ✅ Includes `?error=admin_access_denied` for UI message
- ✅ Falls back to login if no account assigned

## 🎯 Architecture Clarification

### `/admin` Routes (Platform-Level)
- **Who:** SUPER_ADMIN only
- **Account Context:** NOT required (account-agnostic)
- **Purpose:** Manage all accounts, platform-wide view
- **Access:** Middleware checks `user.role === 'SUPER_ADMIN'`

### `/app` Routes (Account-Scoped)
- **Who:** ADMIN, MANAGER, VIEWER (account-scoped users)
- **Account Context:** REQUIRED via `?account={slug}`
- **Purpose:** Manage single account's data
- **Access:** Middleware checks authenticated + auto-injects account context

### Separation of Concerns
```
┌─────────────────────────────────────────┐
│ /admin (Platform Admin)                 │
│ - SUPER_ADMIN only                      │
│ - No account context needed             │
│ - Views/manages all accounts            │
│ - Account selection happens INSIDE      │
└─────────────────────────────────────────┘

┌─────────────────────────────────────────┐
│ /app (Customer Admin)                   │
│ - ADMIN/MANAGER/VIEWER                  │
│ - Account context required (?account=)  │
│ - Views/manages single account          │
│ - Account comes from user.accountId     │
└─────────────────────────────────────────┘
```

## 🔄 User Flows

### SUPER_ADMIN Flow
1. **Login:** Enter email → magic link
2. **Callback:** Upsert User with `role: SUPER_ADMIN`, `accountId: null`
3. **Redirect:** → `/admin` (no account context)
4. **Access:** Can view all accounts, select one to drill down

### Regular Admin Flow
1. **Login:** Enter email → magic link
2. **Callback:** Upsert User with `role: ADMIN`, `accountId: <assigned>`
3. **Redirect:** → `/app?account={slug}` (account context included)
4. **Access:** Can only view their assigned account's data

### Edge Cases Handled
- ✅ SUPER_ADMIN tries to access `/app` → allowed (for testing accounts)
- ✅ Regular admin tries to access `/admin` → redirected to `/app` with account
- ✅ User with no account assigned → error page with clear message
- ✅ `/app` accessed without `?account=` → auto-injected from user.accountId
