# Account Selector & Link Fix

**Date:** 2026-01-26  
**Status:** ✅ COMPLETE

---

## Overview

Fixed mock account selection system to be deterministic and account-scoped. The login flow now treats accounts as the primary selection (not roles), and all links are properly scoped to the selected account's data.

---

## 🎯 Changes Made

### 1. Login Page Redesign (`app/login/page.tsx`)

**Before:** Role-based authentication with technical labels  
**After:** Account-based selection with business-friendly labels

**Changes:**
- Renamed "mockAdmins" → "mockAccounts"
- Updated UI copy: "VoxSignal Admin" → "VoxSignal"
- Simplified account cards: focus on account name and description
- Button text: "Login as X" → "Continue as X"
- Removed technical jargon (roles, account IDs)
- Customer admins always route to `/app` (their account home)

**Selection Flow:**
1. User selects account: Platform Admin, Acme Coffee, or TechConf Events
2. Click "Continue as [Account]"
3. Sets cookies: `mock_admin_email`, `mock_admin_role`, `mock_account_id`
4. Routes to:
   - Platform Admin → `/admin`
   - Customer Admin → `/app`

**Result:** Clean, business-focused account selector

---

### 2. AdminLayout Navigation (`components/admin/AdminLayout.tsx`)

**Before:** Hardcoded links to `/admin/events/default-kiosk-event` and `/kiosk`  
**After:** Dynamic, context-aware navigation

**Changes:**
- Added props: `kioskEventId?: string`, `homePath?: string`
- Updated brand: "Booth Audio" → "VoxSignal"
- Logo: "B" → "V"
- Removed hardcoded "Events" link
- Made "Home" link use `homePath` prop (defaults to `/admin`)
- Made "Kiosk →" link use `kioskEventId` when provided
- Footer text updated to VoxSignal

**Kiosk Link Logic:**
```typescript
const kioskUrl = kioskEventId ? `/kiosk?eventId=${kioskEventId}` : '/kiosk'
```

**Props Usage:**
- **Platform Admin (`/admin`):** No props → generic `/kiosk` link
- **Customer Admin (`/app`):** Pass `homePath="/app"` and `kioskEventId={firstEventId}`

**Result:** Navigation adapts to user's context automatically

---

### 3. Customer Admin Home Page (`app/app/page.tsx`)

**Changes:**
- Extract first active event from account data
- Pass `homePath="/app"` to AdminLayout
- Pass `kioskEventId={firstEvent?.id}` to AdminLayout

**Code:**
```typescript
const firstEvent = locations
  .flatMap((loc) => loc.events)
  .find((event) => event.isActive && event.status === 'ACTIVE')

return (
  <AdminLayout 
    homePath="/app"
    kioskEventId={firstEvent?.id}
  >
```

**Result:** Kiosk link in nav points to account's first active event

## 📝 Cookie → Header → API Flow

### Middleware (`middleware.ts`)

```typescript
// 1. Read cookie
const mockAccountId = request.cookies.get('mock_account_id')?.value

// 2. Set header
requestHeaders.set('x-account-id', session.accountId)
```

### API Route (`app/api/app/account/route.ts`)

```typescript
// 3. Read header
const accountId = request.headers.get('x-account-id')

// 4. Query database
const account = await prisma.account.findUnique({
  where: { id: accountId },
  include: {
    locations: {
      include: {
        events: { ... }
      }
    }
  }
})
```

**Result:** Account data automatically scoped to authenticated user
