# Production Deployment Guide - User Table Fix

## 🎯 Quick Summary

**Problem:** `public.User` table doesn't exist in production  
**Cause:** Toxic migration `20260127012625_add_user_model` failed to apply  
**Solution:** Mark toxic migration as applied, deploy safe migration  
**Estimated Time:** 2-3 minutes  
**Downtime:** None (additive operations only)  

---

## ✅ PRE-FLIGHT CHECKLIST

Before deploying, verify:

- [ ] You have production database credentials in `.env.prod`
- [ ] You have `npx` and `dotenv-cli` installed (`npm install -g dotenv-cli`)
- [ ] You can connect to production database
- [ ] You have backup/snapshot of production database (recommended)

---

## 🚀 DEPLOYMENT STEPS

### Option A: From GitHub Actions (RECOMMENDED)

Add this to your CI workflow:

```yaml
name: Fix Production User Table

on:
  workflow_dispatch: # Manual trigger

jobs:
  deploy-user-table:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - uses: actions/setup-node@v3
        with:
          node-version: '18'
      
      - name: Install dependencies
        run: npm ci
      
      - name: Setup production env
        run: |
          echo "DATABASE_URL=${{ secrets.PROD_DATABASE_URL }}" > .env.prod
          echo "DIRECT_URL=${{ secrets.PROD_DIRECT_URL }}" >> .env.prod
      
      - name: Mark toxic migration as applied
        run: |
          npx dotenv -e .env.prod -- prisma migrate resolve --applied 20260127012625_add_user_model
      
      - name: Deploy safe migrations
        run: |
          npx dotenv -e .env.prod -- prisma migrate deploy
      
      - name: Verify User table exists
        run: |
          npx dotenv -e .env.prod -- prisma db execute --stdin <<< "SELECT COUNT(*) as user_table_exists FROM information_schema.tables WHERE table_schema = 'public' AND table_name = 'User';"
```

FROM information_schema.columns

- email (text)
- role (UserRole enum)
- accountId (text, nullable)

- createdAt (timestamp)
- updatedAt (timestamp)

**Expected values:**
- SUPER_ADMIN
- ADMIN
- MANAGER
- VIEWER

### 3. Check Indexes Exist

## 🐛 TROUBLESHOOTING

### Issue: "Migration already applied"

**Error:**
```
Migration `20260127012625_add_user_model` has already been applied.
```

**Solution:** This is expected if you already ran step 1. Skip to step 2.

---

### Issue: "Table already exists"

**Error:**
```
ERROR: relation "User" already exists
```

**Solution:** 
- This means the User table already exists in prod
- The safe migration will skip creation (idempotent guards)
- Continue with `prisma migrate deploy` - it will mark as applied and continue

---

### Issue: "Cannot resolve migration"

**Error:**
```
Migration `20260127012625_add_user_model` is not in a failed state.
```

**Solution:**
- Check migration status: `npx dotenv -e .env.prod -- prisma migrate status`
- If it shows as "Pending", run: `npx dotenv -e .env.prod -- prisma migrate resolve --applied 20260127012625_add_user_model`
- If it shows as "Applied", skip step 1 and go to step 2

---

### Issue: Database connection fails

**Error:**
```
Can't reach database server at...
```

**Solution:**
1. Verify `.env.prod` has correct `DATABASE_URL`
2. Check firewall/VPN access to production database
3. Verify database credentials are correct
4. Check if database is running

## 🔄 ROLLBACK PLAN (Just in Case)

If something goes wrong, you can rollback:

### Rollback User Table Creation
```sql
-- Connect to production database
DROP TABLE IF EXISTS "User" CASCADE;
DROP TYPE IF EXISTS "UserRole";

-- Then fix the migration status
DELETE FROM "_prisma_migrations" 
WHERE migration_name IN (
  '20260127012625_add_user_model',
  '20260129000000_add_user_table_safe'
);
```

**Warning:** This will delete all User records. Only do this if:
- You just deployed and immediately found an issue
- No users have logged in yet
- You have a database snapshot to restore from
