**Date:** 2026-01-26  
**Status:** ✅ IMPLEMENTED

## Overview

Implemented a clean surface split between platform admin and customer admin areas with proper authentication guards and DB-driven navigation.

---

## 🏗️ Architecture

### Three Distinct Surfaces

| Surface | Route | Access | Purpose |
|---------|-------|--------|---------|
| **Platform Admin** | `/admin/**` | SUPER_ADMIN only | Manage customer accounts |
| **Customer Admin** | `/app/**` | Account-scoped admins | Manage own account's data |
| **Public Kiosk** | `/kiosk` | Public (no auth) | Voice capture interface |

---

## 🔐 Authentication & Authorization

### Middleware (`middleware.ts`)

**Route Protection:**
- `/admin/**` → SUPER_ADMIN role required
- `/app/**` → Signed-in user with accountId required
- `/kiosk` → Public access (no auth)
- `/api/**` → Application logic handles auth

**Headers Added (for /app routes):**
- `x-account-id` - User's account ID
- `x-admin-email` - User's email
- `x-admin-role` - User's role (ADMIN, MANAGER, VIEWER)

- Uses cookies: `mock_admin_email`, `mock_admin_role`, `mock_account_id`

## 📊 Data Model

### Admin Model (Already in Schema)

```prisma
model Admin {
  id        String    @id @default(cuid())
  email     String    @unique
  name      String?
  password  String
  accountId String?   // NULL = global admin, set = account-scoped
  role      AdminRole @default(ADMIN)
  isActive  Boolean   @default(true)
  account   Account?  @relation(fields: [accountId], references: [id])
  
  @@index([accountId])
  @@index([role])
}

enum AdminRole {
  SUPER_ADMIN  // Full system access
  ADMIN        // Account-level admin
  MANAGER      // Location-level manager
  VIEWER       // Read-only access
}
```

### Account → Location → Event Hierarchy

- **Account**: Customer account (Acme Coffee, TechConf)
- **Location**: Physical location (SF store, NYC store)
- **Event**: Feedback collection event at a location
- **Response**: Individual survey response
- **Answer**: Answer to a specific question

## 🎯 Key Implementation Details

### 1. Middleware Guards

```typescript
// /admin/** - SUPER_ADMIN only
if (pathname.startsWith('/admin')) {
  if (session.role !== 'SUPER_ADMIN') {
    return 403 Forbidden
  }
}

// /app/** - Account-scoped access
if (pathname.startsWith('/app')) {
  if (!session.accountId) {
    return 403 Forbidden
  }
  // Add accountId to headers for API routes
  requestHeaders.set('x-account-id', session.accountId)
}
```

### 2. Account-Scoped API Verification

```typescript
// Verify event belongs to user's account
const event = await prisma.event.findFirst({
  where: {
    id: eventId,
    location: {
      accountId: accountId, // From middleware header
    },
  },
})

if (!event) {
  return 404 Not Found
}
```

### 3. DB-Driven Navigation

```typescript
// No hardcoded event IDs!
const account = await prisma.account.findUnique({
  where: { id: accountId },
  include: {
    locations: {
      include: {
        events: {
          where: { isActive: true },
          orderBy: { createdAt: 'desc' },
        },
      },
    },
  },
})

// Render locations → events hierarchy
```
