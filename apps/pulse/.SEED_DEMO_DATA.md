# Demo Data Seed Implementation

**Date:** 2026-01-26  
**Status:** ✅ WORKING

---

## Overview

Created `prisma/seed.ts` to generate realistic demo data for existing events:
- 25 responses per event
- Full answer pipeline (Answer → Transcript → Analysis → ProcessingLog)
- Realistic sentiment distribution (50% positive, 35% negative, 15% neutral)
- Idempotent (safe to re-run)

---

## 🌱 Usage

```bash
# Seed multi-tenant structure first (accounts, locations, events)
npm run db:seed:multi-tenant

# Then seed demo responses
npx prisma db seed
# or
npm run db:seed
```

**Full Reset:**
```bash
# Reset database, run all migrations, seed structure + demo data
npx prisma migrate reset --force
```

## 📊 What Gets Created

For each active event in the database:

### Response (×25 per event)
- `anonymousId`: `demo-user-1`, `demo-user-2`, etc.
- `status`: `COMPLETED`
- `startedAt`: Random time in last 7 days
- `completedAt`: Random time in last 7 days
- `metadata`: `{ source: 'seed-script', demoData: true }`

### Answer (×questions per response)
- `questionKey`: From event's `questionsJson`
- `promptLabel`: Question text
- `objectKey`: `demo/{eventId}/{responseId}/{questionKey}.webm`
- `objectEtag`: Random etag
- `mimeType`: `audio/webm`
- `fileSizeBytes`: 50KB-200KB (random)
- `durationMs`: 5-30 seconds (random)
- `status`: `COMPLETED`

### AnswerTranscript (×1 per answer)
- `provider`: `openai`
- `model`: `whisper-1`
- `text`: Realistic feedback text (see data below)
- `wordsJson`: null

### AnswerAnalysis (×1 per answer)
- `provider`: `openai`
- `model`: `gpt-4-turbo-preview`
- `promptVersion`: `v1.0`
- `summary`: Truncated feedback text
- `sentimentScore`: 0.0-1.0 (weighted distribution)
- `sentimentLabel`: Positive/Negative/Neutral
- `themesJson`: 2-4 relevant themes
- `actionsJson`: 1-3 action items with impact levels

### AnswerProcessingLog (×3 per answer)
- UPLOAD → TRANSCRIBE → ANALYZE pipeline
- Realistic timestamps (70s, 60s, 50s ago)
- Success status (no errors)

## ✅ Idempotency

The seed is safe to re-run:

```typescript
// Check existing responses before creating more
const existingCount = await prisma.response.count({
  where: { eventId: event.id },
})

const targetCount = 25
const neededCount = Math.max(0, targetCount - existingCount)

if (neededCount === 0) {
  console.log('Already has 25 responses, skipping')
  continue
}

// Only create what's needed
for (let i = 0; i < neededCount; i++) {
  // Create response...
}
```

**Result:**
- First run: Creates 25 responses per event
- Second run: Skips events that already have 25+
- Can manually delete responses and re-run to regenerate

## 🔧 Migration Fix Applied

**Problem:** Old migrations created Response with required `attendeeId` and Answer with required `answerType`, but new schema doesn't have these fields.

**Solution:** Added to `20260124211951_add_account_location_multi_tenancy/migration.sql`:

```sql
-- Make old Response columns nullable
DO $$ BEGIN
  ALTER TABLE "Response" ALTER COLUMN "attendeeId" DROP NOT NULL;
EXCEPTION
  WHEN undefined_column THEN NULL;
END $$;

-- Make old Answer columns nullable
DO $$ BEGIN
  ALTER TABLE "Answer" ALTER COLUMN "answerType" DROP NOT NULL;
EXCEPTION
  WHEN undefined_column THEN NULL;
END $$;

DO $$ BEGIN
  ALTER TABLE "Answer" ALTER COLUMN "questionId" DROP NOT NULL;
EXCEPTION
  WHEN undefined_column THEN NULL;
END $$;

DO $$ BEGIN
  ALTER TABLE "Answer" ALTER COLUMN "language" DROP NOT NULL;
EXCEPTION
  WHEN undefined_column THEN NULL;
END $$;
```

This makes the migration additive and backward-compatible.

## 🔄 Development Workflow

### Fresh Start
```bash
# 1. Reset database and apply migrations
npx prisma migrate reset --force --skip-seed

# 2. Seed multi-tenant structure
npm run db:seed:multi-tenant

# 3. Seed demo responses
npm run db:seed
```

### Add More Demo Data
```bash
# Just run seed again (idempotent)
npm run db:seed

# If events already have 25+ responses, no new data is created
# To regenerate, delete responses in Prisma Studio first
```

### Reset Demo Data Only
```bash
# Delete all responses (keeps accounts/locations/events)
npx prisma db execute --stdin <<< "DELETE FROM \"Response\" WHERE anonymousId LIKE 'demo-user-%';"

# Re-seed demo data
npm run db:seed
```
