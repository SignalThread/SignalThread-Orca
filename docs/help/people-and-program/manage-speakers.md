# Manage Speakers

Maintain speaker profiles, assignments, files, communications, notes, onsite details, and portal access.

## Overview

Internal Notes are not shown in the speaker portal.

A conflict means session assignments require schedule review.

## When You’ll Use It

- Open this guide when you need to maintain speaker profiles, assignments, files, communications, notes, onsite details, and portal access.
- Return before program publishing, external communication, and onsite handoff when people or readiness data changes.

## Before You Begin

- Open the correct event and search Event Directory before creating a new person.
- Editing requires event editor access; external speaker links do not grant planner access.

## Open Speakers

1. Expand **Event Directory** and select **Speakers**.
2. Use **Add Speaker**, **Upload CSV**, readiness filters, and a speaker row to open the speaker workspace.

## Build the Speaker List

1. Open Directory, then Speakers.
2. Select **Add Speaker** for one person or **Upload CSV** to open **Import Speakers from CSV**.
3. Search and filter the speaker directory for readiness gaps, status, or conflicts.
4. Open a speaker to work in **Overview**, **Profile**, **Sessions**, **Files**, **Documents**, **Communications**, **Submissions**, **Conflicts**, **Activity**, **Onsite**, or **Notes**. **Email History** appears within Communications.

## Understand Important Concepts

- Internal Notes are not shown in the speaker portal.
- A conflict means session assignments require schedule review.

## In-product Helper Text

> Speakers is for program participants; Directory remains the canonical identity record.

## Planner Tips

- Create the speaker record as soon as participation is likely, then distinguish invited, confirmed, and readiness work through the available status and completeness fields.

## Best Practices

- Create the speaker early, then use readiness filters as deadlines approach.
- Keep planner-only context in internal notes, not in speaker-facing messages.

## Troubleshooting

### A control is missing or disabled

Check the canonical Directory person, your event role, and any review or token state described in this article.

## Frequently Asked Questions

### Where is the system of record?

Event Directory owns canonical identity and roles. The speaker workspace owns profile, readiness, files, submissions, communications, portal access, and onsite details for the speaker role.
