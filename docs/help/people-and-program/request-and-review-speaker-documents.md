# Request and Review Speaker Documents

Track required speaker documents and review files submitted against those requests.

## Overview

A speaker file and a required-document request are related but distinct records.

Docs Hub review and speaker-file review have their own statuses.

## When You’ll Use It

- Open this guide when you need to track required speaker documents and review files submitted against those requests.
- Return before program publishing, external communication, and onsite handoff when people or readiness data changes.

## Before You Begin

- Open the correct event and search Event Directory before creating a new person.
- Editing requires event editor access; external speaker links do not grant planner access.

## Open Request and Review Speaker Documents

1. Open a speaker and select **Documents** or **Files**.
2. Create the request in **Documents**; review an uploaded file in **Files** when it arrives.

## Create a Document Request

1. Open a speaker and choose Documents.
2. Create the required document request and indicate whether a signature is required when supported.
3. Share or confirm portal access so the speaker can see the request.
4. Monitor request and submission state.

## Review a Speaker File

1. Open Files or the related document request.
2. Download or inspect the submitted file.
3. Choose the available file-review outcome and add feedback when the file-review controls are shown.
4. Link the request to Docs Hub when the supported action is appropriate for the event record.

## Understand Important Concepts

- A speaker file and a required-document request are related but distinct records.
- Docs Hub review and speaker-file review have their own statuses.

## In-product Helper Text

> Required Documents tells the speaker what must be submitted for this event.

## Planner Tips

- Name requests for the actual deliverable, such as 'Final presentation deck' or 'Signed release,' and include the operational deadline.

## Best Practices

- Name requests for the deliverable and deadline, such as Final presentation deck or Signed release.
- Use speaker Documents for the request and Files for uploaded-file review; link final event records to Docs Hub when supported.

## Troubleshooting

### A control is missing or disabled

Check the canonical Directory person, your event role, and any review or token state described in this article.

## Frequently Asked Questions

### Where is the system of record?

The speaker **Documents** section owns speaker-specific requests and submitted files. Docs Hub separately owns general event documents and their review state.
