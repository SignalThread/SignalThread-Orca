# Assign Speakers to Sessions

Connect confirmed speakers to the correct Run of Show sessions and review schedule conflicts.

## Overview

Only event speakers can be assigned through the speaker module. Create or import the speaker first when they are missing.

## When You’ll Use It

- Open this guide when you need to connect confirmed speakers to the correct Run of Show sessions and review schedule conflicts.
- Return before program publishing, external communication, and onsite handoff when people or readiness data changes.

## Before You Begin

- Open the correct event and search Event Directory before creating a new person.
- Editing requires event editor access; external speaker links do not grant planner access.

## Open Assign Speakers to Sessions

1. Open **Run of Show**, select a session, and open **Speakers**.
2. Select **Add {speaker name}**, then select **Save changes**.

## Assign a Speaker

1. Open Run of Show and select the session.
2. Open Speakers in the quick module or session workspace.
3. Choose an existing event speaker.
4. Save the assignment and review any conflict indicator.

## Review From the Speaker

1. Open Speakers and select the speaker.
2. Open Sessions.
3. Review all assigned sessions and any Conflict badge.
4. Return to Run of Show to correct timing or assignments.

## Understand Important Concepts

- Only event speakers can be assigned through the speaker module. Create or import the speaker first when they are missing.

## In-product Helper Text

> Speaker conflicts are based on assigned session timing.

## Planner Tips

- Assign rehearsals and speaker-ready times when they are modeled as sessions; this makes overlap review more realistic.

## Best Practices

- Create the speaker record before the session assignment.
- Review all assigned sessions from the speaker workspace after resolving a conflict.

## Troubleshooting

### A control is missing or disabled

Check the canonical Directory person, your event role, and any review or token state described in this article.

## Frequently Asked Questions

### Where is the system of record?

Event Directory owns speaker identity. Run of Show owns each session assignment and the schedule data used to detect speaker conflicts.
