# Read-Only Access and Permission Problems

Determine whether organization context, event role, approval state, or platform role prevents an action.

## Start Here

1. Confirm you selected the organization that owns the event.
2. Verify the event appears in your visible event list.
3. Check whether your event role is Viewer or another read-only role.
4. Check whether the record is approved, locked, or in a state that prevents editing.
5. For platform administration, confirm you have SUPER_ADMIN access.
6. Ask the appropriate administrator to change access; do not create a duplicate event or record as a workaround.

## If the Problem Continues

Record the event name, affected record, action you attempted, visible status, and exact error text. Share that context with the appropriate Orca administrator without including secure portal or intake tokens.

## Best Practices

- Confirm organization, event, role, and record state in that order.
- Ask an administrator to correct access rather than recreating the event or record.
