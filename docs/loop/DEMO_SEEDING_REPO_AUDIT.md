## Storage and environment decisions

No schema changes in Loop 1. A local ownership journal is operational metadata only, containing exact persisted row receipts, database target identity, canonical scope and content fingerprint. It cannot confer membership or manufacture a product mapping. Borrowed attach records are never reset-owned; changed rows or unowned FK effects refuse reset. Adapter transactions must re-check before deletion. Partial writes without a durable receipt must fail closed, never be adopted by a matching prefix.

Known Platform Core ref in repository: `wtbnpeluwhjjqccdofxd`; current Orca operational ref: `qgxvtgnzptepimuawnku`. Knowing a ref does not establish a non-production target or authorize access. No credentials were read and no database was contacted. The controller explicitly requires human review before commands requiring secrets/credentials/live access. Mutation target establishment and persisted seed validation are prerequisites for Loop 2.

The worktree has no installed `node_modules`. Loop 1 can run its Node-native tests directly and use the already-installed local toolchain from the main checkout for static checks, without installing dependencies or modifying another worktree.
